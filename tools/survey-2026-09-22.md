# Free-Tool Survey for the Swarm — 2026-09-22

**Mission:** find actively-maintained, free, self-hostable tools that take operational load off Rock (lead agent, Linux VM) and the 5 PC agents (Windows 11, Ollama/qwen3, OpenClaw gateway). Prime directive: free tools do the labor; paid tokens buy judgment. Everything on the PC runs hidden/headless.

**Method:** 40 candidate repos checked against the GitHub API on 2026-09-22. "Actively maintained" = commit pushed within the last ~6 months and not archived. 6 repos failed the cut (Fooocus, AUTOMATIC1111 webui, Mochi, LTX-Video, Wan2.1, Mixpost — all quiet 6+ months) and are noted, not recommended.

**Standing rule for deployment:** heavy Docker stacks go on the **Linux VM**. The **Windows PC** stays lean and responsive — only GPU media work and logged-in browser automation live there.

## TOP 5 BY ROI FOR THIS SWARM

### 1. Postiz — self-hosted social scheduler with an agentic API
- **GitHub:** https://github.com/gitroomhq/postiz-app
- **License:** AGPL-3.0 (verified via API)
- **What:** Self-hosted Buffer/Hootsuite replacement; schedules and publishes to 17+ platforms (X, Instagram, Threads, Facebook, LinkedIn, TikTok, YouTube, Reddit, Mastodon, Bluesky…).
- **Deploy:** Linux VM (Docker: Node.js + PostgreSQL + Redis).
- **Load it takes off Rock:** Absorbs the entire hand-rolled queue/publisher/cross-post system — scheduling, per-platform formatting, retry logic, analytics snapshots. Its API is explicitly designed as a native endpoint for n8n/AI-agent pipelines, so Hammer/Scribe can POST finished drafts instead of Rock babysitting JSON queue files and cron sweeps.
- **Gotchas:** AGPL-3.0 (fine for internal use; only matters if you ever distribute it). Each platform still needs its own official OAuth/API connection — Postiz doesn't bypass platform auth. Analytics are lighter than Sprout/Buffer. No mobile app. ~2 vCPU / 2 GB RAM minimum.

### 2. n8n — self-hosted workflow automation with AI agent nodes
- **GitHub:** https://github.com/n8n-io/n8n
- **License:** Fair-code (Sustainable Use License) — **not** OSI open-source. Free to self-host with no execution limits; you just can't sell hosted n8n-as-a-service.
- **What:** Visual workflow builder + code nodes (JS/Python), 400+ integrations, first-class AI Agent nodes, LangChain/tool support, vector-store nodes.
- **Deploy:** Linux VM (`docker run -p 5678:5678 n8nio/n8n`).
- **Load it takes off Rock:** Replaces the sprawling cron + bespoke Python glue holding the social engine together (draft → QC → queue → publish → engagement → cross-post). Recurring missions, bank-keeper refills, and PC-agent dispatch become visual workflows with retries, error branches, and run history instead of fragile shell scripts Rock has to debug at midnight.
- **Gotchas:** Fair-code license — read it if monetization ever touches it. Self-hosting means owning updates/backups (Rock already owns the VM, so this is natural). Someone has to learn the node model; start with one pipeline (e.g., IG publish sweep) before migrating everything.

### 3. LiteLLM — one LLM gateway with fallbacks, retries, and spend tracking
- **GitHub:** https://github.com/BerriAI/litellm
- **License:** MIT (verify — GitHub API returned NOASSERTION on the license field)
- **What:** OpenAI-compatible proxy in front of 100+ LLM providers. One endpoint, with fallback chains, retries, load balancing, and per-key budget tracking.
- **Deploy:** Linux VM, in front of the PC's Ollama tunnel and the paid xAI route.
- **Load it takes off Rock:** **This is the credit doctrine as infrastructure.** Point every agent's LLM calls at LiteLLM once: configure Ollama-first → xAI-fallback routing, per-agent token budgets, and automatic logging of every paid fallback and its reason. No more hand-rolled fallback code in drafter.py; the "paid xAI only as genuine last resort" rule becomes config, not code Rock maintains.
- **Gotchas:** Adds one more hop (small latency). The proxy itself must stay up — put it behind the same keepalive discipline as the Ollama tunnel. Recent versions moved the core to Rust; the Python SDK/API surface is unchanged.

### 4. Mem0 (+ Qdrant) — persistent memory so the swarm stops forgetting
- **GitHub:** https://github.com/mem0ai/mem0 (Apache-2.0) · https://github.com/qdrant/qdrant (Apache-2.0)
- **What:** Mem0 is a drop-in memory layer for AI agents — it extracts, stores, and recalls facts across sessions. Qdrant is the high-performance vector DB backing it (also usable standalone for RAG over docs).
- **Deploy:** Linux VM (both are Docker-friendly; Qdrant is a single lightweight binary).
- **Load it takes off Rock:** Directly answers David's ask: *"a knowledge and brain base so we don't forget things and log what we learned."* Each PC agent (Scout/Hammer/Scribe/Analyst/Critic) gets long-term memory: what worked, what flopped, voice corrections, mission outcomes. Rock stops re-briefing agents and stops losing trial-and-error lessons between sessions. Qdrant doubles as searchable RAG over the private swarm-coordination repo (docs, post-mortems, prompt templates).
- **Gotchas:** Memory needs curation — wire Critic (or a scheduled pass) to prune stale/low-value memories or the store fills with noise. Embeddings can run local (nomic-embed-text via Ollama) to keep it fully free. Mem0's hosted cloud exists; self-host the open-source core.

### 5. browser-use — AI-driven browser automation
- **GitHub:** https://github.com/browser-use/browser-use
- **License:** MIT (verified via API)
- **What:** Agents that operate a real browser to accomplish goals ("generate an image of X on Gemini and download it") instead of brittle step-by-step scripts.
- **Deploy:** Windows PC (it must drive David's logged-in Chrome profile for Gemini/social).
- **Load it takes off Rock:** Hardens the single most fragile part of the stack: the hand-rolled Playwright scripts for Gemini image/video generation and social posting. An AI-driven loop recovers from UI changes, popups, and layout drift that would silently break today's scripts at 3 AM. Rock stops writing per-site selectors.
- **Gotchas:** It needs an LLM "brain" per run — point it at local Ollama for simple tasks to keep it free; complex pages may still want a stronger model (budget this deliberately). Heavier and slower than raw Playwright; keep Playwright for the hot paths that already work, use browser-use for the flaky ones. Respect the one-browser-job-at-a-time lock — browser-use doesn't know about it unless you wrap it.

## Suggested adoption order (least effort → most leverage)

1. **Uptime Kuma** (afternoon) — stop discovering outages by accident.
2. **LiteLLM proxy** (a day) — credit doctrine as config; every agent points at one endpoint.
3. **Postiz** (a weekend) — migrate one platform's publishing first (e.g., X), then the rest.
4. **Mem0 + Qdrant** (a weekend) — wire into the PC agents' mission loop; backfill from the private repo.
5. **n8n** (ongoing) — migrate cron+script glue pipeline by pipeline; don't big-bang it.
6. **ComfyUI or InvokeAI** — gated on Scout's GPU survey. If the PC has ≥8 GB VRAM, this kills the browser-Gemini dependency for images.
7. **browser-use** — for the flakiest browser scripts, after the core above is stable.
8. **Wiki.js / RAGFlow** — when the knowledge base outgrows flat markdown in the private repo.
